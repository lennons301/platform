```markdown
# Architecture Diagrams Standard

Every project maintains C4 architecture diagrams as PlantUML source files
in `docs/architecture/`.

## Required Diagrams

All projects must include at minimum:

| File | C4 Level | Purpose |
|------|----------|---------|
| `context.puml` | L1 System Context | The system, its users, and external dependencies |
| `containers.puml` | L2 Container | Deployable units (web app, API, database, etc.) |

## Optional Diagrams

Tracked per project in the product YAML's `architecture.diagrams` list:

| File pattern | C4 Type | When to include |
|-------------|---------|-----------------|
| `components-<name>.puml` | L3 Component | Complex subsystems warranting internal breakdown |
| `deployment.puml` | Deployment | Maps containers to infrastructure per environment |
| `dynamic-<name>.puml` | Dynamic | Runtime flows (CI/CD pipelines, key request paths) |

## Format

- Use [C4-PlantUML](https://github.com/plantuml-stdlib/C4-PlantUML) library includes.
- Source `.puml` files are the primary artifact — locally renderable in any IDE with a PlantUML extension.
- Rendered `.svg` files are generated by CI into `docs/architecture/rendered/` and committed back.
- Mark rendered SVGs as binary in `.gitattributes`:
  ```
  docs/architecture/rendered/*.svg binary
  ```

## Maintenance

Diagrams must be updated when architecture changes materially: new containers,
new external systems, changed deployment topology. Not every code change
requires a diagram update.

Three mechanisms help enforce freshness:

1. **Implementation plan convention** — plans that change architecture include
   a diagram update task.
2. **CI staleness detection** — the conformity check warns when
   architecture-relevant files are newer than the diagrams.
3. **PR-level nudge** — a GitHub Action comments on PRs that touch
   architecture-relevant files without also updating diagrams.

## Product YAML

Each product YAML includes an `architecture` section:

```yaml
architecture:
  diagrams:
    - context
    - containers
  staleness_paths:
    - docker-compose.yml
    - vercel.json
```

`context` and `containers` are enforced as minimum regardless of what is listed.
Additional entries declare optional diagrams the project commits to maintaining.

`staleness_paths` lists files whose changes suggest diagrams may need updating.
Defaults are applied if omitted: `docker-compose.yml`, `vercel.json`,
`supabase/`, and common deployment config files.

## Templates

Use `templates/architecture/` from the platform repo as a starting point for
new projects. Skeleton diagrams include placeholders for project name and
description.
```

### Task 3: Create the conformity check script

**Files:**
- Create: `checks/check-architecture.sh`

- [ ] **Step 1: Write the check script**

`checks/check-architecture.sh`:

```bash
#!/usr/bin/env bash
# Check architecture diagram conformity for a single project.
# Usage: check-architecture.sh <project-path> <product-yaml-path>

source "$(dirname "$0")/lib.sh"
require_yq

PROJECT_PATH="$1"
PRODUCT_YAML="$2"
ARCH_DIR="$PROJECT_PATH/docs/architecture"
ISSUES=()
WARNINGS=()

# Check for documented divergence
if has_divergence "$PRODUCT_YAML" "architecture-diagrams"; then
  echo -e "  architecture: ${DIVG} (intentional divergence)"
  exit 0
fi

# 1. Check docs/architecture/ directory exists
if [ ! -d "$ARCH_DIR" ]; then
  echo -e "  architecture: ${FAIL} (no docs/architecture/ directory)"
  exit 1
fi

# 2. Check mandatory diagrams exist
for diagram in context containers; do
  if [ ! -f "$ARCH_DIR/$diagram.puml" ]; then
    ISSUES+=("missing mandatory $diagram.puml")
  fi
done

# 3. Check optional declared diagrams exist
DIAGRAM_COUNT=$(yq eval '.architecture.diagrams | length' "$PRODUCT_YAML" 2>/dev/null)
if [ "$DIAGRAM_COUNT" != "null" ] && [ "$DIAGRAM_COUNT" != "0" ] && [ -n "$DIAGRAM_COUNT" ]; then
  for i in $(seq 0 $((DIAGRAM_COUNT - 1))); do
    diagram=$(yq eval ".architecture.diagrams[$i]" "$PRODUCT_YAML")
    # Skip mandatory ones already checked
    if [ "$diagram" = "context" ] || [ "$diagram" = "containers" ]; then
      continue
    fi
    # Check for exact match or pattern match (components-*, dynamic-*)
    found=false
    if [ -f "$ARCH_DIR/$diagram.puml" ]; then
      found=true
    elif ls "$ARCH_DIR"/${diagram}-*.puml 1>/dev/null 2>&1; then
      found=true
    fi
    if [ "$found" = false ]; then
      ISSUES+=("declared diagram missing: $diagram")
    fi
  done
fi

# 4+5. Validate C4 content in each .puml file
if ls "$ARCH_DIR"/*.puml 1>/dev/null 2>&1; then
  for puml_file in "$ARCH_DIR"/*.puml; do
    basename=$(basename "$puml_file")
    # Check for C4-PlantUML include
    if ! grep -q '!include.*C4_' "$puml_file"; then
      ISSUES+=("$basename: no C4-PlantUML include")
    fi
    # Check for at least one C4 model element
    if ! grep -qE '(Person|System|Container|System_Boundary|System_Ext|ContainerDb|Deployment_Node|Rel)\(' "$puml_file"; then
      ISSUES+=("$basename: no C4 model elements found")
    fi
  done
fi

# 6. Check rendered SVGs exist
if ls "$ARCH_DIR"/*.puml 1>/dev/null 2>&1; then
  for puml_file in "$ARCH_DIR"/*.puml; do
    basename=$(basename "$puml_file" .puml)
    if [ ! -f "$ARCH_DIR/rendered/$basename.svg" ]; then
      WARNINGS+=("rendered/$basename.svg missing (CI may not have run)")
    fi
  done
fi

# 7. Staleness check
if [ ${#ISSUES[@]} -eq 0 ] && ls "$ARCH_DIR"/*.puml 1>/dev/null 2>&1; then
  # Get last commit touching diagrams
  diagram_commit=$(git -C "$PROJECT_PATH" log -1 --format='%ct' -- "docs/architecture/*.puml" 2>/dev/null || echo "0")

  # Get staleness paths from YAML or use defaults
  STALE_PATHS=()
  STALE_COUNT=$(yq eval '.architecture.staleness_paths | length' "$PRODUCT_YAML" 2>/dev/null)
  if [ "$STALE_COUNT" != "null" ] && [ "$STALE_COUNT" != "0" ] && [ -n "$STALE_COUNT" ]; then
    for i in $(seq 0 $((STALE_COUNT - 1))); do
      STALE_PATHS+=($(yq eval ".architecture.staleness_paths[$i]" "$PRODUCT_YAML"))
    done
  else
    # Defaults
    STALE_PATHS=("docker-compose.yml" "docker-compose.yaml" "vercel.json" "supabase/")
  fi

  for path in "${STALE_PATHS[@]}"; do
    if [ -e "$PROJECT_PATH/$path" ] || ls "$PROJECT_PATH"/$path 1>/dev/null 2>&1; then
      path_commit=$(git -C "$PROJECT_PATH" log -1 --format='%ct' -- "$path" 2>/dev/null || echo "0")
      if [ "$path_commit" -gt "$diagram_commit" ] 2>/dev/null; then
        WARNINGS+=("diagrams may be stale ($path changed more recently)")
        break
      fi
    fi
  done
fi

# Report
if [ ${#WARNINGS[@]} -gt 0 ]; then
  for warning in "${WARNINGS[@]}"; do
    echo -e "  architecture: ${WARN} ($warning)"
  done
fi

if [ ${#ISSUES[@]} -eq 0 ]; then
  if [ ${#WARNINGS[@]} -eq 0 ]; then
    echo -e "  architecture: ${PASS}"
  fi
  exit 0
else
  echo -e "  architecture: ${FAIL} (${ISSUES[*]})"
  exit 1
fi
```

`templates/architecture-render.yml.tmpl`:

```yaml
# Architecture Diagram Renderer
# Copy to .github/workflows/architecture-render.yml in your project repo.
name: Render Architecture Diagrams

on:
  push:
    branches: [main, master]
    paths:
      - 'docs/architecture/*.puml'

jobs:
  render:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4

      - name: Create output directory
        run: mkdir -p docs/architecture/rendered

      - name: Render PlantUML to SVG
        run: |
          docker run --rm \
            -v "${{ github.workspace }}/docs/architecture:/data" \
            plantuml/plantuml \
            -tsvg -o /data/rendered /data/*.puml

      - name: Commit rendered diagrams
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add docs/architecture/rendered/*.svg
          if git diff --cached --quiet; then
            echo "No diagram changes to commit"
          else
            git commit -m "chore: render architecture diagrams [skip ci]"
            git push
          fi
```

- [ ] **Step 2: Create the PR review nudge template**

`templates/architecture-review.yml.tmpl`:

```yaml
# Architecture Review Nudge
# Copy to .github/workflows/architecture-review.yml in your project repo.
# Customise the paths list below to match your project's staleness_paths.
name: Architecture Review Nudge

on:
  pull_request:
    paths:
      # Customise these paths to match your product YAML's staleness_paths
      - 'docker-compose.yml'
      - 'docker-compose.yaml'
      - 'vercel.json'
      - 'supabase/**'
      - 'drizzle/**'
      - 'Dockerfile'
      - 'infrastructure/**'

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Check if diagrams were updated
        id: check
        run: |
          CHANGED=$(git diff --name-only origin/${{ github.base_ref }}...HEAD -- docs/architecture/)
          if [ -z "$CHANGED" ]; then
            echo "needs_review=true" >> "$GITHUB_OUTPUT"
          else
            echo "needs_review=false" >> "$GITHUB_OUTPUT"
          fi

      - name: Comment on PR
        if: steps.check.outputs.needs_review == 'true'
        uses: actions/github-script@v7
        with:
          script: |
            const body = '**Architecture review nudge:** This PR modifies files that may affect the system architecture, but no diagrams in `docs/architecture/` were updated. Please check whether the C4 diagrams need updating.';
            const { data: comments } = await github.rest.issues.listComments({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
            });
            const existing = comments.find(c => c.body.includes('Architecture review nudge'));
            if (!existing) {
              await github.rest.issues.createComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: context.issue.number,
                body,
              });
            }
```
